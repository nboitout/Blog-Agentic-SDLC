Module01 — Core model

The Agent Loop

An agent query uses the same loop as Claude Code: read context, decide, act, observe — repeat until Claude finishes or a limit stops the run.

init reports session setup. ResultMessage reports how the run ended, with cost and usage. These are events your application receives.

Source: Agent loop and message types. Diagram uses Python message type names.

Module02 — Interception

Hooks: Pre / PostToolUse

Hooks sit inside the loop, not beside it — intercepting a call before it runs, or rewriting its result after, without touching the tool's own code.

One field now covers both tool families: updatedToolOutput replaces output for any tool — MCP or built‑in. The older updatedMCPToolOutput is deprecated.

Source: Hook decisions and output fields.

Module03 — Packaged know-how

Skills

A skill packages instructions for a kind of task. Claude loads them when it invokes the skill; you can also request a skill by name.

Discovered

Listed, not loaded

Claude sees short descriptions of the skills available to this session. Full instructions load when a skill is invoked.

Loaded on demand

Pulled in mid‑task

When a request matches, Claude invokes the Skill tool and loads the relevant instructions into the active context — e.g. a docx skill only when a Word file is due.

Composable

Stack when needed

Several skills can combine in one task — a research skill to gather facts, then a document skill to format the result.

Skills must be discovered through your configured settings sources and enabled for the session. The skills option controls which ones Claude may invoke.

Source: Configure and invoke skills.

Module04 — Control

Permissions

Read these checks in order. A call can be approved, blocked, or sent for a decision before it reaches the last step.

  1. 1Hooks

    Can block, defer or edit a call. A hook’s approval still goes through deny and ask rules.

  2. 2Deny rules

    A matching deny rule blocks the call. The approval callback is skipped.

  3. 3Ask rules

    A match goes to the callback for a decision, or is denied in dontAsk mode.

  4. 4Permission mode

    May approve the call or apply extra checks. For example, acceptEdits approves eligible file edits.

  5. 5Allow rules

    An eligible match approves the call. Calls needing no approval also finish here.

  6. 6Your callback

    canUseTool / can_use_tool decides remaining calls. In dontAsk, they are denied instead.

Modes: default · acceptEdits · plan · auto · dontAsk · bypassPermissions.
Already-approved calls skip your callback. Use a PreToolUse hook for checks that must see every call.

Source: Permission order and exceptions. Some protected actions always need extra checks.

Custom Tools

Module06 — Delegation

Subagents

A subagent works in its own context. The parent receives its returned result rather than the full working transcript, while the application can optionally observe intermediate activity.

Source: Subagent context and returned reports.

Module07 — Continuity

Sessions

A session_id identifies a conversation. Its history is saved locally by default, so a later run can pick up where it left off. You can also mirror it to external storage.

A fork copies the conversation history. It does not copy your files: edits in the same working directory are visible to both sessions.

Source: Continue, resume and fork sessions.

Module08 — Connections

External MCP Servers

Connect local or remote MCP servers through stdio, SSE, or Streamable HTTP. Tool Search loads tool definitions when needed and is on by default where supported.

Module09 — Limits

Runtime Limits & Effort

Limit tool-use turns, set an estimated spending threshold, and choose how much reasoning Claude applies to each response.

maxTurns

Tool-use turn limit

Stops with error_max_turns. Keep earlier streamed messages: this error has no final result answer.

maxBudgetUsd

Budget threshold

Stops when estimated spend reaches the threshold, checked after each response. That response and running subagents can push the total higher.

effort

Reasoning depth

low to max — trades speed and token cost for reasoning depth. Available levels depend on the model.

For example, a $1 threshold can finish above $1. Leave headroom, and use billing records for the actual charge.

Sources: Limits and effort · Cost estimates. Option names here are TypeScript.

Module10 — Memory

Context Compaction

When context fills up, the runtime summarizes older conversation history and keeps recent exchanges so Claude can continue. Some older details can be lost.

PreCompact runs before compaction; compact_boundary marks it afterward. Put lasting project rules in CLAUDE.md, loaded through your settings sources.

Source: Compaction and persistent instructions.
