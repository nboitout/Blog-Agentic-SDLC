When GitHub is the control plane, billing should read like a rulebook.

A clearer explanation of Anthropic's June 15, 2026 billing change for GitHub-centered, spec-driven delivery. The architecture can stay sophisticated, but the billing rule is simple: GitHub holds the work graph, while Claude billing depends on invocation mode.

Billing map
Billing follows invocation mode.

Interactive Claude usage stays on subscription. Programmatic usage moves to separate Agent SDK credit.

Effective date: June 15, 2026 GitHub remains the control plane

Quick scan

Read the billing map before the workflow

Programmatic usage

Claude Agent SDK, non-interactive claude -p, Claude Code GitHub Actions, and third-party apps built on the Agent SDK move to separate Agent SDK credit.

Interactive usage

Interactive Claude Code in the terminal or IDE, orchestrator logic inside a human-driven session, and subagents inside that same session stay on subscription usage.

GitHub artifacts

GitHub issues, PRs, workflow state, and repository artifacts remain control-plane signals. They are not Anthropic billing items by themselves.

Narrative flow

The workflow now reads like a sequence, not a dense poster

  1. 01
    GitHub artifact

    Repo spec and GitHub issues

    Execution-ready specs live in the repository while Issues or Projects track the work graph.

    • Specs are versioned close to code
    • User stories and tasks stay visible in GitHub
    • Planning context remains attached to delivery artifacts
  2. 02
    Workflow trigger

    GitHub event starts execution

    An issue update, workflow trigger, or project transition makes the selected work item agent-ready.

    • Project state changes stay visible in GitHub
    • Triggers can come from issues, projects, or workflows
  3. 03
    Billing follows invocation mode

    Main Claude orchestrator reads context

    The orchestrator reads repo spec and GitHub context, plans the user story, and delegates tasks.

    • Interactive Claude Code session: stays on subscription usage
    • Agent SDK or non-interactive invocation: moves to separate Agent SDK credit
  4. 04
    Role label does not define billing

    Sub-agents execute scoped tasks

    Subagents generate code, run tests, open PRs, and update GitHub status using scoped task context.

    • Subagents inside the same interactive session stay on subscription
    • SDK-defined or automated subagents use separate Agent SDK credit
  5. 05
    Automation branch

    Programmatic path or clarification loop

    Automated execution either produces a ready PR through CI or loops back for clarification.

    • Successful automated coding and CI path is programmatic usage
    • Clarification can return to GitHub workflow without becoming a billing item by itself
  6. 06
    GitHub control plane

    User story completion in GitHub

    GitHub tracks status updates, PR reviews, merge readiness, and closure once the work is resolved.

    • Status updates stay visible to the team
    • PR review and merge signals close the loop
Decision fork

The only branch that matters for billing

Programmatic path

Automated PR and CI execution

If the work is executed through the Agent SDK, a non-interactive Claude path, or GitHub automation, usage goes to separate Agent SDK credit.

Interactive path

Human-driven orchestration session

If the same orchestration and subagent work happens inside an interactive Claude Code session, it stays on subscription usage.

Decision table

Answer the billing question in one glance

Invocation Billed as Why
Interactive Claude Code in IDE or terminal Subscription usage Human is driving the session
Subagent invoked inside that same interactive session Subscription usage Billing inherits the invocation mode
Agent SDK workflow or claude -p automation Separate Agent SDK credit Programmatic invocation
Claude Code GitHub Actions or automated CI path Separate Agent SDK credit Automation path is non-interactive
GitHub issue, PR, workflow state, or artifact Not an Anthropic billing item Control-plane metadata
